# Adrobot

Создаватор кампаний и редактор офферов для **Keitaro Admin API v1**.
Python 3.12+, FastAPI, SQLite, обычный JavaScript. Интерфейс на русском, без сборки фронтенда.

## Запуск

### Docker

```bash
git clone https://github.com/viktorgit/adrobot.git
cd adrobot
cp .env.example .env
# Заполните KEITARO_BASE_URL и KEITARO_API_KEY в .env
docker compose up --build -d
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).
Для остановки: `docker compose down`. SQLite хранится в именованном томе `adrobot-data`;
обычная остановка его не удаляет.

### Локально с uv

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/), затем:

```bash
cp .env.example .env
# Заполните .env
uv sync --frozen --group dev
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

В PowerShell для копирования используйте `Copy-Item .env.example .env`.
Если Python ещё не установлен: `uv python install 3.13`.

После создания `.venv` приложение можно запустить без команды uv:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

## Настройки

| Переменная | Назначение |
|---|---|
| `KEITARO_BASE_URL` | Корень трекера, например `https://tracker.example`, без `/admin` |
| `KEITARO_API_KEY` | Ключ Admin API с доступом к кампаниям, потокам, офферам и справочникам |
| `DATABASE_PATH` | Путь SQLite, по умолчанию `data/adrobot.sqlite3` |
| `APP_ACCESS_TOKEN` | Необязательный отдельный токен доступа к интерфейсу/API Adrobot |

Ключ Keitaro используется только сервером. `.env`, база данных и результаты живых проверок
исключены из Git и Docker build context. Пароль от админки приложению не нужен.

По умолчанию приложение доступно только с локального компьютера. При необходимости внешнего
доступа настройте HTTPS/reverse proxy, `APP_ACCESS_TOKEN` и разрешённые хосты в `app/main.py`.
Интерфейс спрашивает токен приложения и хранит его в `sessionStorage` до закрытия вкладки;
API принимает `Authorization: Bearer <APP_ACCESS_TOKEN>`. Это однопользовательский инструмент,
не система с аккаунтами и ролями.

## Как пользоваться

1. **Новая кампания.** Введите название, один или несколько ISO-кодов стран, ID оффера
   (или найдите его в каталоге). Выберите домен, группу и источник из Keitaro.
   Группа/источник `FORTESTS` выбираются автоматически, если доступны.
2. **Создание.** Кампания получает ротацию по позиции. Первый активный поток с фильтром
   `country / accept` отправляет выбранные страны на `https://www.google.com/`.
   Второй активный поток без фильтров отправляет остальных на оффер с долей 100%.
   Кампания включается только после создания обоих потоков. При ошибке потоков неполная
   кампания переносится в архив; при неудаче компенсации интерфейс сообщает её ID.
3. **Редактор.** Найдите кампанию по имени или ID. При первом открытии потоки загружаются
   из Keitaro; последующие открытия показывают сохранённое рабочее состояние.
4. **Черновик.** Добавление, удаление, восстановление и закрепление веса сохраняются в SQLite.
   Жёлтая карточка означает неопубликованные изменения. Изменение числа закрепляет вес;
   кнопка «Закреплён» снимает закрепление и выравнивает свободные доли.
5. **Опубликовать.** Отправляет офферы только выбранного потока. Удалённые офферы
   исчезают из Keitaro, но остаются серыми в локальном архиве с кнопкой «Вернуть».
6. **Отменить.** Возвращает поток к последней загруженной/опубликованной версии, включая веса
   и закрепления. Добавленные только в черновик привязки исчезают.
7. **Загрузить из Keitaro.** Импортирует изменения из админки. Известный оффер, исчезнувший
   из потока, попадает в локальный архив. Перед синхронизацией нужно опубликовать или отменить
   черновики. Потоки без схемы офферов показываются без разбора их настроек; удалённые потоки
   сохраняются для просмотра.

Кнопки удаляют **привязку к потоку**, а не сам оффер в Keitaro.
Черновики, закрепления и архив переживают перезапуск сервера и браузера.

## Правила весов

- Используются целые проценты, как в Admin API: для трёх офферов — `34 / 33 / 33`.
- Закреплённые веса сохраняются, остаток делится поровну между свободными офферами.
  Остаточные единицы получают первые офферы в порядке потока.
- Пример: закреплённые `25%` и два свободных оффера → `25 / 38 / 37`.
- Удалённые/отключённые офферы получают 0% при пересчёте.
- Нельзя закрепить более 100% или оставить активному свободному офферу менее 1%.
  Поэтому при целых процентах поддерживается до 100 активных офферов в одном потоке.
- Если все веса закреплены, их сумма должна составлять 100%.
- Пустой поток можно оставить в черновике, но нельзя опубликовать.
- При загрузке сохраняются исходные веса Keitaro: пересчёт выполняется только при редактировании.

## Архитектура и ограничения

```text
Браузер → FastAPI → CampaignService → Keitaro Admin API
                        ↓
                     SQLite
```

- `app/keitaro.py` — HTTP-контракт, TLS-проверка, таймауты, обработка ошибок.
  Повторяются только запросы чтения при сбое установления соединения. Запись не повторяется.
- `app/service.py` — создание, синхронизация, архив, черновики и публикация.
- `app/weights.py` — детерминированное распределение целых процентов.
- `app/store.py` — SQLite/WAL, транзакции и версии документов.
- `app/main.py`, `app/schemas.py` — REST API, проверка данных и HTTP-защита.
- `app/static/` — адаптивный интерфейс без сторонних JS/CSS-зависимостей.

SQLite хранит по одному JSON-документу на кампанию: снимки потоков Keitaro, последнюю
опубликованную версию и текущие привязки. Для небольшого однопользовательского задания это
позволяет атомарно изменять весь черновик без миграций множества связанных таблиц.
Архив существует только в локальной базе: при её удалении историю удалённых привязок
восстановить из Keitaro невозможно. Для резервной копии остановите приложение и скопируйте
каталог `data` (или том Docker).

Каждая операция требует `revision`: устаревшая вкладка получает HTTP 409. Перед публикацией
сравниваются актуальные офферы/схема Keitaro с исходным снимком. Публикация отправляет только
поле `offers`, поэтому фильтры, лендинги, редиректы и другие настройки не перезаписываются.
У Keitaro нет атомарного compare-and-swap в используемом API: остаётся небольшое окно между
проверкой и записью. Для задания запись сериализована транзакцией SQLite; для нескольких
пользователей и больших кампаний понадобится другой способ координации и фоновая очередь.

POST создания не имеет серверного idempotency key в используемом API. При потере ответа
на запись сначала проверьте результат в Keitaro. Если кампания создана, но импорт не удался,
ошибка содержит её ID, чтобы открыть её повторно без дублирования.

Каталог офферов запрашивается у Keitaro и кэшируется на 30 секунд. Поиск по ID/названию и
пагинация выполняются сервером приложения. Доступность оффера дополнительно проверяется
при добавлении, восстановлении и публикации. Метрики кликов/дохода не входят в задание.

## API и проверки

[Swagger UI](http://127.0.0.1:8000/docs) · [OpenAPI JSON](http://127.0.0.1:8000/openapi.json)

| Метод | Маршрут | Действие |
|---|---|---|
| GET | `/api/campaigns?q=...&offset=0&limit=25` | Поиск кампаний |
| POST | `/api/campaigns` | Создание кампании |
| GET | `/api/metadata`, `/api/offers?q=...` | Справочники и каталог |
| GET | `/api/campaigns/{id}` | Локальное состояние |
| POST | `/api/campaigns/{id}/sync` | Импорт из Keitaro |
| POST | `/api/campaigns/{id}/streams/{sid}/offers` | `add`, `remove`, `restore`, `pin`, `unpin` |
| POST | `/api/campaigns/{id}/streams/{sid}/publish` | Публикация |
| POST | `/api/campaigns/{id}/streams/{sid}/cancel` | Отмена |
| GET | `/health` | Проверка сервера, без запроса к Keitaro |

Для операций записи нужен `Content-Type: application/json`. Первый `sync` принимает `null`,
повторный — `{"revision": N}`. Редактирование принимает `revision`, `action`, `offer_id`
и необязательный `share` для закрепления. Публикация и отмена принимают `{"revision": N}`.

```bash
uv run pytest -q
uv run ruff check .
uv run ruff format --check app tests scripts
node --check app/static/app.js
```

Тесты используют `httpx.MockTransport` с реальными формами ответов Keitaro; сеть и ключ не нужны.
GitHub Actions запускает проверки на Linux и Windows. Отдельная живая проверка:

```bash
uv run python -m scripts.smoke_live --confirm-test-writes
```

Она создаёт собственную кампанию `test_viktor_adrobot_<случайный суффикс>`, проверяет создание
двух потоков, черновик/отмену, публикацию, удаление/восстановление, pin и внешнее изменение
потока, затем архивирует только эту кампанию. Требуется `.env` с реальным тестовым трекером
и минимум три активных оффера. Другие кампании скрипт не изменяет.

Проверено 17.11.2026: 36 тестов, Ruff, синтаксис JavaScript, полный сценарий с реальным
Keitaro и интерфейс в браузере на настольной и мобильной ширине. Тестовые кампании
архивированы. Docker-конфигурация приложена, но образ в этой среде не собирался:
Docker здесь не установлен. Для локальной разработки достаточно Python.
